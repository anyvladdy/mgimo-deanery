# Общий журнал агентов

Из корня выполни `npm run team -- log`, чтобы увидеть переписку и передачи работ с временем UTC. Команда `npm run team -- status` показывает занятые пути и их владельцев. Журнал нужен и для короткого ответа «что изменилось с моего прошлого чата?».

### Один рабочий разговор

Команды ниже — пример отдельных действий двух сессий.

```sh
npm run team -- claim web-1 "Экран недели" src/schedule tests/schedule.test.js
npm run team -- say web-1 lead-1 "Модуль подготовит GET /schedule. Подключи его в src/server.js."
npm run team -- log lead-1
npm run team -- say lead-1 web-1 "Подключу маршрут. Идентификатор студента бери из c.get(\"studentId\")."
npm run team -- log web-1
npm run team -- done web-1 "Готов экран недели. npm test прошёл. Интегратору осталось подключить маршрут."
```

- **Перед началом** выбирай отдельное имя для каждой одновременно работающей сессии. Прочитай свой `log`: он включает адресные сообщения, исходящие сообщения и объявления для `all`.
- **Бронь** покрывает указанный файл или всё поддерево. Если занят каталог, взять файл внутри не получится; действует и обратное правило. Набор путей резервируется целиком. При конфликте владелец виден в сообщении, команда завершится с ошибкой.
- **При зависимости** напиши владельцу через `say`. Для общего решения, например изменения формата даты, используй получателя `all`. Доставка идёт через журнал: агенты читают сообщения в начале задачи, перед общей сборкой и перед завершением.
- **Для передачи** владелец записывает через `done`, что успел, чем проверил и что остаётся. После этого другой агент занимает нужные пути через `claim`. Если сессия оборвалась, её бронь сохраняется. После проверки, что она завершена, координатор может продолжить под тем же именем, записать причину передачи и освободить пути.

### Хранение

Файл `journal/team.sqlite` создаётся при первом запуске. SQLite последовательно обрабатывает конкурирующие записи. Бронь и сообщение о ней фиксируются одной транзакцией. Это координация для участников, которые пользуются командами журнала. Сам редактор остаётся доступен человеку.

Все сессии в одной рабочей папке видят один журнал. Для соседних локальных worktree укажи во всех сессиях одну переменную `TEAM_JOURNAL` с абсолютным путём к общему SQLite-файлу. Данные журнала остаются на этом компьютере. Чтобы передать историю в читаемом виде, выполни `node scripts/team.js log > история.txt` в месте, где хочешь сохранить копию.
