# DeepSeek Harness в цифровом деканате

Состав кабинета выбирается при запуске. Один и тот же набор модулей используется для маршрутов, меню, карточек на главной, источников уведомлений, SQL-схем и демоданных. Вход, профиль, сессии, защита форм и общий каркас «Сегодня» доступны в любой сборке.

## Запуск

Из каталога `final_package` выполните нужную команду.

```sh
./start.sh --resume
DEANERY_MODULES=core ./start.sh --fresh
DEANERY_MODULES=full,-schedule ./start.sh --fresh
DEANERY_MODULES=core,+messages ./start.sh --fresh
```

Первая команда запускает полную комплектацию. Вторая оставляет вход и профиль, расписание, успеваемость, заявки и уведомления прототипа. В режиме `full,-schedule` главная показывает доступные разделы и ближайшую аттестацию, уведомления продолжают работать без переносов пар. Режим `core,+messages` добавляет сообщения и офисный вход для ответов.

Параметр `DEANERY_MODULES` принимает `full` или `core`, затем изменения через запятую. `+id` подключает модуль и его обязательные зависимости. `-id` отключает модуль. Модули с отсутствующей обязательной зависимостью пропускаются при запуске. Для переключения на существующей базе перезапустите `npm start` с тем же `DEANERY_DB` и новым `DEANERY_MODULES`.

Локальное демо хранит отдельный набор рабочих копий для каждого выбранного состава. При создании исходной базы терминал один раз выдаёт демо-доступы. `--resume` открывает рабочую копию, `--fresh` создаёт новую рабочую копию из исходной базы этой сборки.

## Подключение нового модуля

Добавьте каталог `src/<id>/` с `module.js`, файлами функции и, при необходимости, `schema.sql` и `seed.sql`. Реестр обнаруживает его при следующем запуске. Модуль получает общие проверки сессии, CSRF и ролей через штатные шлюзы.

- `module.js` экспортирует объект по умолчанию. `id` совпадает с названием каталога. `requires` содержит только зависимости, без которых функция теряет смысл.
- `studentMount({ db, currentSchoolDay })` возвращает пару из префикса и экземпляра Hono. `staffMount({ db })` возвращает `{ path, routes, dashboard }`, где `path` задан относительно `/office`, а `dashboard` может описывать карточку рабочего стола. Для маршрута преподавателя предусмотрено `teachers: true`, для маршрута руководителя — `leadership: true`. Шлюз пропускает офис и администратора, а для преподавателя и руководителя проверяет соответствующий флаг перед вызовом маршрута. Проверку доступа к отдельной записи выполняет модуль. Публичный маршрут регистрируется через `publicMount({ db, session })`.
- `navigation(group, modules)` возвращает пункты вида `[порядок, href, подпись, ключ]`. Доступны группы `studentMain`, `studentTools`, `studentHeader`, `studentFullTools`, `studentServices`, `officeMain`, `staffTools` и `leadershipTools`. Пункты `studentServices` собираются в каталоге `/services`. Пятый элемент ссылки `studentMain` или `studentTools` может указать группу полного меню: `week` для «Учебной недели» или `study` для «Учёбы». `studentHeader` добавляет быстрые переходы в шапку полной версии, `studentFullTools` добавляет ссылки только в её боковое меню. Метки `header` и `home` у `studentTools` оставляют переходы в облегчённом меню и учитывают их место в полной версии. Ссылки без метки попадают в «Кабинет». В `studentServices` пятый элемент может задать внутренний адрес для полной версии. Хук `todayPanel({ db, studentId, student, schoolDay, csrf })` может вернуть карточку из `hono/html` для «Сегодня».
- Межмодульные вызовы проходят через `modulesFor(db).get(id)`. Этот метод возвращает объявленные `services` активного модуля. При его отсутствии покажите доступную часть экрана. Прямые импорты из каталога соседней функции мешают физическому удалению.
- `schema.sql` содержит идемпотентные создания таблиц и индексов владельца. Изменение существующей структуры идёт новой функцией в конце списка `migrations`. Для подготовки данных после создания таблиц есть `afterSchema`, для совместимых демофикстур — `afterSeed`. Инициализация схем выполняется в одной транзакции. Для времени учебного события при записи из HTTP-обработчика используйте `deanery_timestamp()`. Она сохраняет UTC по текущим часам кабинета. Для календарной даты занятия храните дату без времени.
- Календарь подключает сервисы с методом `calendarEvents(db, studentId, { from, to })`. Для разового добавления фикстуры в уже существующую рабочую базу демо укажите `demoUpgrade: true` и добавьте идемпотентный `seed.sql`. Для обновления уже добавленных демофикстур укажите `demoUpgrade: 2` и повышайте число при следующей ревизии. Новая ревизия применяется один раз при открытии демо.
- Чтобы убрать исходники функции, удалите её каталог из сборки и перезапустите приложение. В свежем файле SQLite создаются только таблицы выбранного состава. В рабочей базе отключение сохраняет ранее записанные строки и отметки прочтения. История снова доступна после подключения модуля. Опубликованные данные, от которых зависят оставшиеся учебные сценарии, сохраняют силу.

Проверка состава и изоляции: `node --test tests/harness.test.js`. Она же проверяет матрицу ролей всех реальных офисных разделов. Проверка сценариев полной комплектации: `npm test`.
